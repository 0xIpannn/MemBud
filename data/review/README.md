# Second-reviewer review and adjudication process (PENDING)

**Current status: single reviewer only. A second independent human review has NOT
been performed.** Every label in `data/labels/evaluation-v2.jsonl` is a
single-reviewer exploratory annotation produced during milestone development by
the project owner. No second reviewer has annotated the cases, no disagreements
have been adjudicated, and no inter-annotator agreement statistic exists. This
directory documents the process that must be executed before the labels can be
called independently reviewed; it does not fabricate that review.

## Blind quiz workflow (exact commands)

The blind quiz is the input-only artifact for the second reviewer. It contains
all 36 transition inputs and **no labels**; only the grader reads
`data/labels/evaluation-v2.jsonl`. The reviewer must not author the cases and
must not open the labels file.

1. **Build the quiz** (repeat only if the manifest/case package changes):

   ```bash
   PYTHONPATH=src .venv/bin/python scripts/review_quiz.py \
     --build --output data/review/quiz-v2.html
   ```

   The command verifies the case-file SHA-256 against the manifest and refuses
   to build if a case file contains label-only fields. It prints the embedded
   manifest hash prefix.

2. **Open the quiz offline** by opening `data/review/quiz-v2.html` directly in a
   browser (`file://.../MemBud/data/review/quiz-v2.html`). It has inline CSS/JS,
   makes no network requests, and needs no server.

3. **Fill it in.** Enter the reviewer name, read each case's prior state,
   candidate state, evidence (`supports` and `contradicts`), required claims, and
   declared operations (including DELETE authorization), then choose `ACCEPT`,
   `HOLD`, or `INVALID_INPUT` and optionally add a note. Answers autosave to the
   browser's `localStorage`; the progress indicator shows coverage.

4. **Download the answers JSON** with the button in the quiz. The download is
   named `membud-evaluation-v2-answers-<slug>.json` and has the shape
   `{reviewer, manifest_id, manifest_sha256, answers: {case_id: {decision, note}}}`.
   Send that file to the coordinator. Do not send screenshots or edit the JSON
   by hand.

5. **Grade the answers** against the frozen labels:

   ```bash
   PYTHONPATH=src .venv/bin/python scripts/review_quiz.py \
     --grade ~/Downloads/membud-evaluation-v2-answers-alice.json \
     --reviewer "Alice" \
     --output data/review/agreement-alice.json
   ```

   If `--output` is omitted the report goes to
   `data/review/agreement-<slug>.json`. The grader validates the structure,
   rejects a mismatched manifest identity/hash or reviewer name, allows blank
   decisions, and reports coverage plus overall and per-split agreement. The
   report's `disagreements` list includes each case's full transition summary
   for adjudication.

6. **Adjudicate every disagreement** with
   `data/review/adjudication-template.md`: copy the report rows into a new
   adjudication record, have a third person resolve each one against
   `data/annotation-guidelines.md`, and record the rule applied. Do not
   overwrite `data/labels/evaluation-v2.jsonl`; create a new labels file and
   manifest version as described below.

The grader is the only step that reads labels. The quiz is deliberately built
without them, and cases are displayed in hash order rather than the manifest's
category-grouped order so that ordering cannot hint at the expected decision.

## Process to complete (after a second reviewer is available)

1. **Freeze the case package.** Do not edit cases, labels, or the manifest while
   review is in progress. If a change is unavoidable, create a new manifest
   version and restart review.
2. **Generate the input-only quiz** with `PYTHONPATH=src .venv/bin/python
   scripts/review_quiz.py --build --output data/review/quiz-v2.html`. The quiz
   lists case inputs and blank decisions only; it contains no labels. The older
   `scripts/review_cases.py` sheet still exists for a combined review record,
   but it shows the proposed label, so give the blind quiz to the reviewer
   instead unless the reviewer can hide that block.
3. **Independent annotation.** A reviewer who did not author the cases reads only
   the quiz inputs plus `data/annotation-guidelines.md` and records a decision
   (`ACCEPT`, `HOLD`, or `INVALID_INPUT`), the reason, and any finding-level
   notes. The proposed label must not be shown to the second reviewer before
   they record their own decision. The quiz autosaves and exports the answers;
   the reviewer sends the downloaded answers JSON (or the coordinator retrieves
   it) without editing it.
4. **Compare and record disagreements.** Run `scripts/review_quiz.py --grade` as
   shown above. It validates the answers, allows blank decisions, reports
   coverage, and writes raw agreement counts/rates overall and per split plus a
   disagreement list. Claims are not independent samples; do not report
   claim-level kappa as if claims were independent annotations. Compute Cohen's
   kappa over the three-way decision labels separately from the report's
   per-case rows if a kappa figure is required.
5. **Adjudicate.** A third person (different from both reviewers) resolves each
   disagreement using `data/review/adjudication-template.md`, citing the
   annotation guideline rule that applies. Adjudication decisions are recorded
   per case; unresolved cases are reported, not silently dropped.
6. **Re-freeze.** Write the adjudicated decisions to a **new** labels file and
   manifest version (e.g. `evaluation-v2-reviewed.json`), hash-pin it, and rerun
   the evaluation. Never overwrite the single-reviewer labels in place.
7. **Report honestly.** Report reviewer identities/roles (anonymised as
   needed), number of cases reviewed, raw agreement, kappa, adjudicated case
   list, and any guideline revisions. Until step 6 completes, all v2 metrics
   must be described as single-reviewer exploratory results.

## What may not be claimed

- "Independently reviewed", "double-annotated", "adjudicated gold data", or any
  inter-annotator agreement figure for the current v2 labels.
- That the proposed labels are the only defensible annotation. Reviewers may
  disagree; the process exists because they might.
- Representative-benchmark validity. The set is synthetic (36 cases) and was
  not sampled from production traffic.

`second_review_status` so downstream consumers cannot miss the limitation.

the blind quiz workflow above uses `scripts/review_quiz.py` for building and
grading. Changing the manifest while review is pending would require a new
manifest version, so the README records the newer tool here.

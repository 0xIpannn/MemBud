Before you start

  1. Enter your reviewer name below. Use the same name when running the grader.
  2. Read each case's prior state, candidate state, evidence (note the supports and contradicts claims), required claims, and declared operations, including any structured DELETE authorization.
  3. Choose one decision and optionally add a short note. A blank decision is allowed, but it reduces coverage and cannot be counted as agreement.
  4. Answers autosave in this browser via localStorage. Keep this tab open until you download; clearing browser data or using private mode may lose drafts.
  5. When finished, click Download answers JSON and send that file to the review coordinator. Do not send a screenshot of the page.

Full annotation rules are in data/annotation-guidelines.md. If a case is genuinely ambiguous under those rules, choose HOLD when it is schema-valid and note the ambiguity; choose INVALID_INPUT only when the schema contract is broken before verification.

Decision rubric

ACCEPT

The transition is schema-valid, every required claim is present, every material candidate claim is supported by the supplied evidence or valid prior memory, declared operations match the state change, any DELETE has valid structured authorization, and no contradiction remains unresolved.

HOLD

The transition is schema-valid but has a material verification problem: an omitted required claim, an unsupported or contradicted claim, an unjustified change/removal, unsupported provenance, or an unresolved contradiction against a retained claim.

INVALID_INPUT

The v2 schema contract is broken before verification: for example a DELETE without valid structured authorization, an authorization that references missing evidence or the wrong target, or a candidate state change not declared by a matching operation. Invalid input is never verified or written.

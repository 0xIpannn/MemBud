# MemBud research and development log

Historical record of what was built, run and measured, with the caveats attached to each result. Figures here describe the state **at the time each entry was written**; test counts in particular are snapshots, so run `python -m pytest` for the current number. This is not a quickstart: see the [README](../README.md) and [quickstart](quickstart.md).

## Done

- Canonical transition/evidence/operation schemas, graph and text encodings, deterministic coverage/preservation/faithfulness checks, fail-safe HOLD behavior, guarded JSON storage, and append-only audit records.
- **Milestone 2:** schema version 2 with strict operation-coverage invariants (undeclared insertions/modifications/removals are rejected) and structured DELETE authorization (`source`, `evidence_id`, `target_id`, `rationale`).
- **Milestone 2:** a structural graph verifier that derives its decisions from graph adjacency (evidence-to-claim provenance paths, required-claim reachability, `REVISES`/`DELETES`/`SUPERSEDES` operation edges, `CONTRADICTS` edges, connectivity, and operation/authorization edge consistency), with the exact-claim-set text verifier retained as an independent control and a separate, feature-gated semantic verifier that fails closed to `UNCERTAIN`.
- **Milestone 2:** versioned store format (`schema_version`, monotonic `version`) with legacy-v1 migration, optimistic `expected_version` concurrency control, a POSIX `flock` critical section, atomic ACCEPT-only writes, and stray-temp recovery. A reference backend demonstrates end-to-end write interception; Mem0 source inspection found no safe public pre-commit hook, so no third-party compatibility is claimed.
- A blind human-review quiz (`scripts/review_quiz.py --build` → `data/review/quiz-v2.html`; answers export; `--grade` produces agreement + adjudication list) makes the pending independent second review practical. The quiz contains no labels; the grader reads them only after the fact.
- Paired three-condition runner (unguarded, graph, text), a hash-pinned 12-case v1 set plus a hash-pinned 36-case v2 set (18 dev / 18 held-out) covering valid updates, omission, corruption, unsupported additions, structured deletions, contradictions, and invalid input, with separate labels, metrics, and annotation/protocol documentation. Both sets are **single-reviewed**; the v2 second-review process is prepared (`data/review/`) but no independent human annotation has been collected yet.
- Optional JSON-mode OpenAI-compatible LLM verifier. DeepSeek's official API was used for an exploratory 12-case run with model ID `deepseek-flash` (currently served as DeepSeek-V4.1-Flash-1017 per DeepSeek docs). Full artifacts: `data/results/deepseek-pilot-v1/pilot-summary.json`, `data/results/evaluation-v1-deepseek-metrics.json`, the deterministic rules run at `data/results/evaluation-v1-rules/pilot-summary.json`, and the 9-row rerun at `data/results/deepseek-rerun-v1/merged-pilot-summary.json` with `data/results/evaluation-v1-deepseek-rerun-metrics.json`.
- The original DeepSeek run produced 15 completed decisions and **9 verifier errors** (5 graph, 4 text) that failed closed as HOLD; on completed responses only, faulty-case detection was 4/4 in each condition. All 9 failed rows were then rerun with the same model/settings on the committed manifest: all completed (24,407 reported tokens, 11 request attempts, 0 cache hits), leaving no residual errors. Using the rerun rows in place of the failures, both conditions return the expected **5 ACCEPT / 7 HOLD** across the 12 cases, detect **7/7** faulty transitions, accept **5/5** valid updates, and produce **0** false accepts and **0** false holds on the single-reviewed labels. This small synthetic pilot still does **not** show graph superiority: the conditions are tied.
- Reported token usage: 32,126 from the original run (13 of 24 completions reported usage; 9 failed rows and 2 cache hits reported none) plus 24,407 from the 9-row rerun, for 56,533 combined across 22 of 24 completions; a preliminary paired probe added 5,946. Even at the top of DeepSeek's published per-token range the rerun bounds at roughly $0.10, but the API does not return billed dollars — check the provider billing dashboard for actual spend. Earlier Command Code provider-API attempts returned HTTP 403 and were stopped.

## Rules-only v2 evaluation

- The reproducible `scripts/run_evaluation_v2.py` run (no paid calls; 0 tokens; $0.00) over the 36-case v2 set produced, for graph and text respectively: 14/12/10 versus 16/10/10 ACCEPT/HOLD/INVALID_INPUT. Graph and the fair-text control detect 12/12 gold faulty (HOLD) cases with 0 false accepts on the HOLD-only view; the plain-text baseline detects 10/12 and false-accepts `DEV-13` and `HELD-13`, the two constructed contradiction cases. Graph and fair text accept 14/14 valid updates with 0 false holds, and all conditions handle the 10 expected-invalid transitions identically.
- Only **2 of 36** decisions differ (`DEV-13`, `HELD-13`): graph returns HOLD where text returns ACCEPT. Those cases carry `evidence.contradicts` metadata, which the exact-claim-set text baseline does not consume.
- A **fairness audit** then equalized information access: a fair text control that reads the same contradiction annotations matches the structural graph verifier on **all 26 non-invalid cases** (both 14 ACCEPT / 12 HOLD, 0 false accepts, 36/36 label agreement), while plain text false-accepts the two contradiction cases. The visible graph advantage on this set is therefore attributable to **annotation access, not structural inference**; no decision-level graph advantage is demonstrated here. See `docs/fairness-audit.md`.

## Held-out LLM and semantic run (paid, capped)

A one-shot DeepSeek run on the 18 held-out cases (13 schema-valid + 5 expected-invalid; 39 executed rows) produced, per condition: graph LLM 3 ACCEPT / 10 HOLD / 0 false accepts / 4 false holds (valid accepted 3/7); text LLM 6 / 7 / 0 false accepts / 1 false hold (6/7); semantic (deterministic text + semantic check) 8 / 5 / 1 false accept (HELD-13) / 0 false holds (7/7). It reported 101,231 tokens (59 request attempts, 0 verifier errors, 0 cache hits), estimated at **≤ ≈$0.40** at DeepSeek's top published rate (billed amount unavailable; confirm the provider dashboard).

The LLM graph condition was over-conservative (4 false holds); the semantic condition matched all valid updates but accepted HELD-13, whose contradiction is annotated only in `evidence.contradicts`, which the semantic module did not then consume — the same blind spot the fairness audit found for plain text. With 7 valid + 6 faulty held-out cases this is descriptive only; no superiority claim is made. Details: `docs/llm-heldout.md`.

## Post-Milestone-2 software follow-ups (2026-11-07)

- **Semantic verifier now consumes `evidence.contradicts`.** The appended semantic check deterministically fails with `CONTRADICTED_CLAIM` when a candidate-state claim appears in an evidence contradiction annotation, before and independent of comparator calls; the LLM comparator prompt/version is unchanged so cached responses stay valid. A cache-only rerun of the held-out conditions (0 provider attempts, 0 new tokens, 51 cache hits, 0 misses) leaves graph/text decisions unchanged and flips semantic HELD-13 from ACCEPT to HOLD, moving semantic false accepts 1/6 → 0/6 and faulty detection 5/6 → 6/6. Artifact: `data/results/llm-heldout-v2-rerun/`. No paid calls were made and no superiority claim is implied.
- **Graph-LLM false holds investigated from cache only, then tested with a controlled ablation.** All 52 cached completions were attributed 1:1 to the held-out run; the four graph false holds fail preservation with model reasons citing a null authorization / missing authorizing edge on evidence-backed `REVISE`/`SUPERSEDE` (3/4 graph-only, 1/4 shared with text), and serialization length/token asymmetry is not supported as a cause. 7/52 calls did retry once, so retries affect accounting but not the holds. A G0/G1/G2 ablation then tested the hypotheses: G0 reproduced the four false holds from cache (0 tokens); G1 (omit null authorization keys) converted 2/4 with 0 false accepts on the paired check; G2 (one-sentence policy clarification) converted 4/4 and, on the 13 schema-valid held-out cases, accepted **7/7 valid** with **0/6 false accepts** and **0 false holds**. A dev-split replication (13 cases not used for the diagnosis) then accepted 7/7 valid with 0/6 false accepts, so the clarified prompt was promoted to the default `membud-transition-checks-v2` (legacy v1 remains selectable for archival cache replay). The held-out evaluation was re-run: graph, text, and semantic each 7 ACCEPT / 6 HOLD / 0 false accepts / 0 false holds, with 24,265 new tokens (text only) and no abort. The held-out split was used to select the prompt, so those numbers remain development evidence; the dev replication is the out-of-sample check. Total ablation/replication/re-run spend: 58 provider attempts (51 rows required at least one paid call; retries included in attempts), 141,657 accounted tokens that reconcile exactly (24,829 + 51,657 + 40,906 + 24,265; ≈$0.014–$0.28 at the harness placeholder, not a bill). See `docs/graph-llm-false-holds.md`.
- **Phase 0 productization.** A stdlib-only localhost `membud.service` `/verify` sidecar plus a no-build opencode `tool.execute.before` guard plugin are included in `integrations/opencode/`, with 42 sidecar tests (39 original + 3 added by the 2026-11-19 remediation), a node/bun harness against the real sidecar, and a real opencode 1.19.5 module-load smoke under an offline network namespace. The hook is awaited before tool execution, so a throw denies the call; measured end-to-end hook latency in the committed harness run is 2.0 ms p50 / 3.7 ms p95 (Node) and 1.4 ms p50 / 2.0 ms p95 (bun) on tiny fixtures; host/runtime dependent, so re-measure before quoting. An opt-in live test with a real model (`deepseek/deepseek-flash`, opencode 1.19.5) then confirmed the full path: a HOLD denied the tool before execution with byte-identical host state and the denial surfaced to the model, while an ACCEPT executed and persisted exactly the candidate (≈$0.0005 for the run; `integrations/opencode/live/EVIDENCE.md`, `scripts/run_live_opencode_denial.py`). This is a feasibility spike, not production software; the 1.18.30-typings vs 1.19.5-CLI gap and what is not proven are documented in its README.
- **Mem0 groundwork.** `membud.adapters.mem0_bridge` implements a host-owned staged-proposal path (Mem0-style extracted proposals + prior snapshot → schema-v2 transition → ACCEPT-only reference-backend persistence) with byte-identical HOLD tests. `mem0ai==2.2.1` has no safe public pre-commit hook, so the real integration below is a host-owned *wrapper*, not a hook (`data/mem0-bridge.md`).
- **Guarded real Mem0 integration (2026-11-19).** `membud.adapters.mem0_staged.StagedMem0` runs the real, unmodified `mem0ai==2.2.1` (embedded Qdrant incl. the entity collection, Mem0's SQLite history/messages DB, real spaCy entity linking) on a shadow clone of the host state, derives the complete write set from a state diff, verifies it through the graph verifier, and replays exactly that set onto the live host only on ACCEPT. Tests (38, real Mem0, offline fakes for the LLM/embedder only; no network or paid call) show that for HOLD, REJECTED (including unmodeled writes to a foreign scope, DDL, or history rewrites) and erroring operations the raw bytes of every host file and every write surface (memory points, entity points, history, messages) are **byte-identical**, while the same operation unguarded on a twin host changes each of them; ACCEPT persists exactly the verified staged state with unmodified-Mem0 semantics, and failed commits are compensated. Scope is the pinned stack only: no real LLM, no Qdrant server, no other Mem0 version or store, vectors compared with a 1e-5 tolerance on ACCEPT, Qdrant+SQLite commit is compensated rather than transactional, O(store) cost per write. Details and residual risks: [`docs/mem0-guarded-integration.md`](mem0-guarded-integration.md); evidence `data/results/mem0-guarded-v1/evidence.json` (`scripts/run_mem0_guarded_evidence.py`, env in `requirements-mem0.txt`).
- **Format stabilization.** The transition/store interchange formats now have an executable migration policy: `membud.migrations` (`migrate_transition_to_v2`, `transition_needs_migration`, `store_needs_migration`) plus a normative [`docs/format-policy.md`](format-policy.md) version registry, compatibility matrix, release checklist, and non-guarantees. Archival v1 transitions round-trip as v1 and require an explicit, fail-closed upgrade; legacy stores migrate on the next `ACCEPT` while a `HOLD` stays byte-identical; unknown future versions are rejected. 19 hand-written cross-version tests pin the behavior (13 original + 6 added by the 2026-11-19 remediation).
- **Checkpoint/resume and cost accounting.** Model runs now write an append-only `checkpoint.jsonl` and support `--resume`: the run refuses a mismatched config fingerprint, skips completed rows with zero client calls (including under `--require-cache`), tolerates/repairs a torn final line, and preserves budget/attempt/cache totals. Token-class cost accounting (`membud.cost`) reports input/output/cached/reasoning token estimates with mandatory provenance and hard `verified_billed: false`; both runners accept `--price-*` flags and label every figure as an estimate, never a bill.
- **Paired statistical analysis.** `scripts/analyze_paired_metrics.py` analyses the committed rules and LLM artifacts with paired percentile bootstrap CIs (seed 20261108, 10k resamples), exact McNemar tests, and a sample-size/precision rationale; the deterministic report is `data/results/statistical-analysis/report.json` and the write-up is [`docs/statistical-analysis.md`](statistical-analysis.md). Headline: rules text vs graph differs by 2/26 cases (95% CI [-0.192, 0.000], p=0.5); fair text vs graph and all prompt-v2 LLM pairs have zero discordant cases, so there is neither a superiority nor an equivalence claim. The machinery is ready for a fresh, better-powered evaluation; the current samples (n=13 held-out, n=26 non-invalid rules) are explicitly exploratory.
- **Software review and remediation (2026-11-19).** A four-reviewer adversarial review plus Lead reproduction of every Major finding produced [`docs/software-review-2026-11-19.md`](software-review-2026-11-19.md) (8 Major / 24 Minor / 9 Nit; no Blocker; committed headline results reproduce). The ordered remediation was then applied: resume crash-window recovery and pre-request zero-charge accounting, host-apply-before-shadow-commit plus an explicit `resync_shadow_store` recovery, honest write-status audit fields and documented write/audit ordering, an enforced current-format commit gate with strict `schema_version` typing, `prepared_input` graph validation, corrected claim numbers/provenance (including the dev-split artifact label), owner-only PII logs, structured JSON for sidecar protocol errors, repo-relative artifact paths, and new failure-injection/regression tests. CI (`.github/workflows/tests.yml`) now runs pytest plus the no-model opencode guard harness.
- **Conversation ingestion, transcript grounding, and multi-turn evaluation.** `membud.conversation` adds canonical conversation transcripts (`ConversationTurn`, `ConversationTranscript`), multi-format parsers (`membud`, `openai`, `opencode`, `halumem`, and plain-text/Markdown), transcript-grounded evidence verification (`verify_transcript_grounding`, `verify_with_transcript`, requiring evidence items to resolve to allowed-role turns with verbatim quotes and lexical claim grounding, and verifying `DELETE` authorization intent/target overlap), deterministic and optional JSON-mode LLM extractors (`RuleBasedConversationExtractor`, `LLMConversationExtractor`), and multi-turn session execution (`run_conversation_session`, `python -m membud.conversation`). On the frozen 8-conversation / 28-step synthetic multi-turn set (`data/manifests/conversations-v1.json`, single-reviewer exploratory annotations; 0 paid calls), `unguarded` persisted unsafe memory in 4/8 conversations (`safe_final=4/8`), while `graph` and `text_fair` achieved **17/17** valid acceptance, **10/10** faulty detection, **0/10** false accepts, **28/28** label agreement, and **8/8** safe final states (plain `text` false-accepted `CONV-06-S3`); end-to-end raw-transcript extraction via `RuleBasedConversationExtractor` converged to expected final records on **8/8** conversations (**20/20** steps `ACCEPT`). ## Relational graph hypothesis and downstream QA utility (2026-11-19)

- **Relational hypothesis** ([`docs/relational-hypothesis.md`](relational-hypothesis.md)). A new experiment-only `membud-relational` format (typed triples, trusted/untrusted sources, derived evidence, `same_as` aliases, supersession history). It comes with a seeded 480-case minimal-pair suite (hash-pinned, `data/manifests/relational-v1.json`) covering multi-hop provenance, alias contradictions across records, and supersession chains, stratified by required relational hops (0–4). An independent graph verifier (typed property graph, SCC cycle detection, components, reachability) is compared with **information-matched** text controls that read a lossless flat serialization. With 1 hop, text false-accepts 144/240 faults (optimistic) or false-holds 144/240 valid updates (pessimistic), exactly the cases beyond its reach. 2-hop text false-accepts 96/240. Closure text and graph agree on **480/480** decisions and fail codes. Relational structure needs multi-hop verification, but the advantage comes from **reasoning reach, not the graph representation**. The suite is ready for an LLM graph-vs-text run (not executed; needs spend).
- **Downstream QA utility** ([`docs/qa-utility.md`](qa-utility.md)). Seeded multi-session conversations, a noisy store-aware extractor with five fault types, per-policy gating, and a fixed deterministic QA reader. 200 conversations at each of three fault rates, with paired bootstrap CIs. At fault rate 0.35, full-reach gating (graph or closure text) raises overall exact match from 0.852 to 0.942 (+0.090 [+0.079, +0.101]), removes wrong user answers (0.108 → 0) and fully protects third-party memory (friend EM 0.856 → 1.000). It also turns some wrong answers into **stale** ones (+0.072) by holding malformed real updates. 1-hop optimistic gating recovers only part of the gain (0.897), and 1-hop pessimistic gating (0.250) is far worse than no gate. Simulated data and spec-derived labels; real-dialogue validation is still open.
- Both runs are rules-only and byte-stable (0 paid calls).

## Research status

The graph-vs-text hypothesis remains open, and the fairness audit narrows it considerably: once information access is equalized, the structural graph verifier and a fair text verifier agree on every v2 decision. The visible difference in the earlier comparison came from the text baseline ignoring `evidence.contradicts`, not from graph reasoning. A defensible graph advantage therefore requires relationships a text verifier cannot reconstruct from the same canonical facts (e.g. multi-hop provenance/derivation, entity-relation contradictions across records, temporal ordering), evaluated against a fair-text control that receives the same facts. Until such evidence exists, the repository makes no graph-superiority claim. See `docs/fairness-audit.md` and `docs/technical-report-milestone-2.md`.
